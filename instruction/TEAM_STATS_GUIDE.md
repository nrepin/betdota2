# Как собирать статистику команд на турнире Dota 2

## Источник данных

- **Dotabuff** (`dotabuff.com/esports/leagues/...`, `/esports/teams/...`) отдаёт **403** на curl/скрипты (Cloudflare). Парсить его не надо. Используем только как ссылки для человека.
- **OpenDota API** (`https://api.opendota.com/api`) — бесплатный, без ключа, JSON. ID лиг, команд и матчей **те же, что на Dotabuff** (это ID Valve), поэтому числа из ссылок Dotabuff подставляются напрямую:
  - `dotabuff.com/esports/leagues/19102-blast-slam-viii` → league `19102`
  - `dotabuff.com/esports/teams/9824702-parivision` → team `9824702`
  - `dotabuff.com/matches/<id>` ↔ `api/matches/<id>`
- Лимит: ~60 запросов/мин, 2000/день без ключа. Скрипт делает паузу 1.1 с и повторяет запрос при 429.

## Эндпоинты

| Что | URL |
|---|---|
| Название лиги | `/leagues/{league_id}` |
| Все матчи лиги (id, время, длительность, счёт фрагов, команды, series_id) | `/leagues/{league_id}/matches` |
| Команды лиги (id → name, tag) | `/leagues/{league_id}/teams` |
| Полный матч: пики/баны, игроки, K/D/A, GPM/XPM, урон, варды, преимущество по золоту, первая кровь | `/matches/{match_id}` |
| Справочник героев (id → localized_name) | `/constants/heroes` |

Важные поля матча:
- `picks_bans[]`: `is_pick`, `hero_id`, `team` (**0 = Radiant, 1 = Dire**), `order`. Первый `is_pick` в порядке `order` → кто брал first pick.
- `radiant_score` / `dire_score` — фраги команд; `duration` — секунды; `radiant_win`.
- `radiant_gold_adv[]` — преимущество Radiant по золоту поминутно (индекс = минута).
- `players[]`: `isRadiant`, `name` (про-ник), `position_est` (1–5), `kills/deaths/assists`, `gold_per_min`, `xp_per_min`, `last_hits`, `hero_damage`, `obs_placed`, `sen_placed`, `roshans_killed`, `firstblood_claimed`.

## Как запускать

Скрипт: `scripts/collect_team.py` (Python 3, только стандартная библиотека).

```bash
cd E:/claude/dota
python scripts/collect_team.py --league 19102 --team 9824702      # одна команда
python scripts/collect_team.py --league 19102 --team 2163 --team 36  # несколько
python scripts/collect_team.py --league 19102 --all                # все команды турнира
python scripts/collect_team.py --league 19102 --all --refresh      # турнир идёт — перекачать список матчей
```

- Ответы API кешируются в `raw/` (матчи в `raw/matches/<id>.json`) — повторный запуск по другой команде почти не делает запросов.
- `--refresh` перекачивает список матчей и команд лиги (появились новые игры). `--refresh-matches` — сами матчи (если OpenDota допарсил реплей позже и поля были пустыми).

## Что получается

- `index.html` (в корне `E:\claude\dota`) — разводящая страница (`scripts/render_index.py`, пересобирается автоматически после каждого запуска `collect_team.py`). Сверху фильтр-кнопки по турнирам (выбор запоминается в адресе: `index.html#19102`), под ним — секция на каждый турнир из `data/<league_id>/`: карточки всех команд лиги с логотипами, сортировка по выигранным сериям и винрейту. Клик → `reports/<league>/<team>.html`. Команды, по которым статистика ещё не собрана, показаны бледными без ссылки.
- **Тоталы**: на странице команды блок «Тоталы» — вводишь линию (минуты или убийства на карте), видно сколько карт ушло больше/меньше/ровно и по каким картам (`totals_widget` в `render_html.py`).
- **Аналитика плей-офф** (`scripts/render_analysis.py`): пишется руками в два файла —
  - `analysis/<league_id>.json` — сетка: цвета и слоганы команд, матчи (`stage`, `a`, `b`, оценка шансов `pa` в %; для финала с неизвестным соперником — `b: null` и `scenarios`);
  - `analysis/<league_id>.html` — текст (фрагмент). Плейсхолдеры: `<!--bracket-->` (тёмная шапка с сеткой), `<!--compare:id,id,...-->` (полосы-сравнение, цифры считаются из `data/`), `<!--totals:id,id,...-->` (общий калькулятор тоталов), `<!--logo:id-->`; `<div class=tcard data-team=ID>` — карточка с цветом команды.
  - Результат `reports/<league_id>/analysis.html`; на `index.html` в секции турнира автоматически появляется баннер с сеткой и кнопкой «Читать полный анализ». После сыгранных матчей — обновить json (счёт, следующий соперник) и текст, перезапустить сборщик.
  - CSS-класс `.hero` занят иконками героев — для крупных блоков не использовать (шапка анализа = `.banner`).
- **Дизайн** (после редизайна по скиллу `redesign-existing-projects`): общий `<head>` — функция `head()` в `render_html.py` (шрифт Geist с Google Fonts, без интернета — системный; favicon; description), все стили — токены в `:root` (`render_html.CSS`). Акцент один, «чернильный» (`--accent` = цвет текста, `--on-accent` — текст на нём), без синего. Новые страницы собирать через `head()` + `CSS`, обёртка `<main class=wrap>`.
- **Турнирная сетка** (`scripts/render_bracket.py`, на `index.html` в секции турнира): структура пишется руками в `analysis/<league_id>.bracket.json` — `groups` (команды групп и даты), `deciders` (стыковые матчи), `playoff.upper/lower` (раунды, у матча `id`, `a`, `b`, `next` — куда проходит победитель; последний раунд `upper` — гранд-финал). Счёт серий подставляется сам из `raw/league_<id>_matches.json` (поиск серии пары команд в окне дат этапа), незаполненный соперник (`b: null`) берётся из победителя матча, чей `next` указывает сюда. Линии между матчами рисует JS по `data-next`. Структуру BLAST Slam VIII восстановил по порядку матчей (GSL-группы, стыки 03.10, плей-офф double elimination на 6 команд) — официальный формат не сверялся. Для свежих результатов запускать сборщик с `--refresh`.
- **Линия PARI против статистики** (`scripts/collect_odds.py`, таблица на странице анализа через `<!--odds-->`):
  - Запуск: `python scripts/collect_odds.py --league 19102` — скачивает линию, сохраняет снимок `odds/<league>/latest.json` (история `odds/<league>/<время>.json`, в git не попадает) и пересобирает анализ. Запускать перед матчем, не чаще раза в несколько минут.
  - Источник — открытый JSON-API PARI без браузера и авторизации: `events/listBase` (вся линия), `events/event?eventId=` (все рынки серии и карт), `line/factorsCatalog/tables` (каталог: код коэффициента -> название; кеш `raw/pari_tables.json` на сутки). Хост `line-vk01-w.pb06e2-resources.ru`, ответы бывают gzip.
  - Матчи турнира ищутся по разделу PARI (`"pari_segment"` в `analysis/<league>.json`) и по названиям команд лиги (нормализация без «team/gaming/esports»).
  - Сравнение: вероятность из коэффициентов без маржи против частоты по картам обеих команд на турнире (время, убийства, первая кровь/Рошан/башня, тотал Рошанов и башен, мегакрипы, Ultrakill, Rampage, Beyond Godlike; победа на карте — log5 по винрейтам). Колонка «Перевес»: нет перевеса/небольшой/явный по погрешности выборки.
  - Определения «первая башня» и «Beyond Godlike» взяты из данных OpenDota и могут не совпадать с правилами PARI.
- Тема только светлая (переключатель и тёмные токены удалены по просьбе пользователя).
- Предпросмотр: в `E:\claude\burton\.claude\launch.json` есть конфиг `dota` (`npx serve` на порту 8895, корень `E:\claude\dota`).
- **Адреса страниц** (каждая — отдельный URL, без переключения через #):
  - `index.html` — «Все турниры»: только команды и их статистика, сложенная по всем турнирам (`scripts/aggregate.py`). Карточка ведёт на `reports/all/<team>.html` — тот же отчёт, но по всем картам команды.
  - `tournaments/<league_id>.html` — страница турнира: кнопка анализа, турнирная сетка, команды турнира. Карточки ведут на `reports/<league_id>/<team>.html`.
  - Сверху на обеих — вкладки-ссылки (`nav()` в `render_index.py`). Ссылки «← страница турнира» / «← все команды» берут адрес из `league_page()` в `render_html.py`.
  - Страница турнира — отдельный файл, а не `reports/<id>/index.html`: адрес папки без `/` на конце ломает относительные ссылки (проверено на `npx serve`).
- **Новый турнир** = просто запустить сборщик с другим `--league`: появится папка `data/<id>/`, кнопка в фильтре и секция на index. Ничего руками не править.
- Логотипы команд скачиваются один раз в `assets/teams/<team_id>.png` (url из `raw/league_<id>_teams.json`, поле `logo_url`).
- На странице команды — плашка «Турнир: <название>» и ссылка «← все команды турнира» (ведёт на `index.html#<league_id>`).

- `data/<league>/<team>.json` — всё: каждая карта (соперник, сторона, W/L, длительность, фраги, first pick, первая кровь, золото на 10-й мин, макс. отрыв/отставание, рошаны, пики/баны обеих сторон, статистика 5 игроков) + `summary`.
- `reports/<league>/<team>.html` — тот же отчёт как страница (`scripts/render_html.py`): плитки с ключевыми цифрами, графики длительности и фрагов по картам, иконки героев (скачиваются один раз в `assets/heroes/` и подключаются относительным путём — отчёт работает без интернета; если появился новый герой — удалить `raw/heroes.json`, он перекачается вместе с картинкой), фраги в формате `свои:чужие (всего)`, сортировка таблиц кликом по заголовку, светлая/тёмная тема. Пересобрать только HTML из готового JSON: `python scripts/render_html.py data/19102/parivision.json`.
- `reports/<league>/<team>.md` — читаемый отчёт:
  - итог: карты/серии, винрейт, средняя/мин/макс длительность (отдельно в победах и поражениях), фраги свои/пропущенные/всего, убийства в минуту, % первой крови, золото на 10-й, рошаны, винрейт за Radiant/Dire и first/second pick;
  - серии со счётом;
  - таблица карт со ссылками на Dotabuff;
  - игроки: позиция, средние K/D/A, KDA, GPM, XPM, добивания, урон, варды, пул героев с W/L;
  - пики команды с винрейтом, баны команды и против команды, против каких героев играли.

## Проверки

- Число карт команды сверить с Dotabuff на странице команды/лиги (открыть во встроенном браузере, если нужно — curl не пустит).
- Если у матча пустые `picks_bans` или `position_est` — реплей ещё не распарсен: подождать или запросить парс `POST /request/{match_id}`, потом `--refresh-matches`.
- Названия команд берутся из `/leagues/{id}/teams`; в списке матчей лиги `radiant_team_name` бывает `null` — это нормально.
- Для нового турнира поменять только `--league` (и id команд).

## Расписание, текущие/архивные турниры, переключатель статистики

- `scripts/render_schedule.py --league <id>` — таблица серий + ближайшее расписание (из линии PARI, `odds/<id>/schedule.json`) на странице турнира. Настройка в `analysis/<id>.schedule.json`: `pari_segment`, `aliases` (названия команд у PARI → в лиге), `bo`. Результаты считаются из `raw/league_<id>_matches.json`.
- На `index.html` турниры делятся на «Текущие» (последний матч не старше 3 суток, `CURRENT_DAYS` в `render_index.py`) и «Архивные» (приглушены opacity); во вкладках архив тоже бледнее.
- На странице команды сверху переключатель «Общая статистика / <турнир>» (`scope_switch` в `render_html.py`) — ведёт между `reports/all/<team>.html` и `reports/<league>/<team>.html`.
- **Герои** (`scripts/heroes_stats.py`, страница `heroes.html`, вкладка «Герои»): темп героя — быстрый/затяжной — считается только по сыгранным картам из `data/*/` (файлы `raw/matches`), без внешних выборок: средняя длительность карт с героем минус средняя по всем, со сглаживанием на малую выборку; меньше 4 пиков — «мало данных». На странице матча блок «Герои по картам»: драфты сыгранных карт с цветом по темпу и «темпом драфта», плюс лайв-карта из OpenDota `/live` (снимок при сборке и обновление в браузере раз в 30 с, если API разрешает запросы с сайта).
- **Прогнозы ИИ** (`scripts/render_forecasts.py`, страница `forecasts.html`, вкладка справа рядом с «Герои»): условный учёт ставок по `forecasts/`. Перевес «явный» — 200 $, «небольшой» — 100 $ (`STAKES`); выигрыш = ставка × (коэф − 1), проигрыш = −ставка. Лайв-прогнозы (сохранённые после старта матча) идут в зачёт и помечены «лайв». Реальные ставки не делаются.
- **Вышки** (`heroes_stats.tower_stats`): урон по вышкам в минуту (`tower_damage`/длительность) у каждого героя; индекс = отклонение от среднего на той же позиции (`position_est`) / средний урон игрока, со сглаживанием; ≥ +0.3 — «быстро ломает», ≤ −0.3 — «медленно ломает» (`TOWER_T`). На страницах: значки ▲/▼ у героев в драфтах, колонки на «Герои» и на странице команды, строка про вышки в «Оценке драфтов» и в `/live`. Связь драфта по вышкам с длительностью и убийствами считается leave-one-out (`corr_dur`, `corr_kills`); на 103 картах r ≈ −0.04 и −0.08, поэтому на ожидаемую длительность и тотал убийств индекс не влияет, а выводится как справка. Когда выборка вырастет и |r| ≥ 0.2, подключить к оценке.
