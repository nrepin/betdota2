# /dota — линия PARI против статистики

Работает в `E:\claude\dota`. Подробности про данные — `instruction/TEAM_STATS_GUIDE.md`. Запуск из корня проекта, для вывода с кириллицей ставить `PYTHONIOENCODING=utf-8`.

Аргумент — название турнира («PARI Universe»), ссылка Dotabuff (`.../leagues/20395-...` → id лиги `20395`) или пусто (тогда взять текущий турнир с главной, см. шаг 1).

## Шаги

1. **Определить турнир.**
   - Раздел в PARI: `python scripts/collect_odds.py --find [слово]` — печатает Dota-разделы линии (id, число матчей, название). Выбрать подходящий. Если матчей 0 или раздела нет — сказать, что линия не открыта, и остановиться.
   - Лига OpenDota: id из ссылки Dotabuff или из `data/` (папки = id лиг). Если лиги нет в `data/` — сначала собрать статистику: `python scripts/collect_team.py --league <id> --all` (долго, запускать в фоне; правила — в TEAM_STATS_GUIDE).
   - Если неясно, какой турнир, — спросить пользователя.
2. **Настроить связку (один раз на турнир).** Файл `analysis/<league>.schedule.json`:
   `{"pari_segment": "<часть названия раздела PARI>", "aliases": {"1w team": "1win"}, "bo": 3}`.
   `aliases` — как PARI называет команду → как в лиге. Если скрипт печатает «не сопоставлено: A - B», добавить алиасы и запустить заново. `--segment "<часть названия>"` переопределяет раздел для разового запуска.
3. **Скачать линию и получить разбор.**
   `python scripts/collect_odds.py --league <id> --text`
   - Сохраняет снимок `odds/<id>/latest.json` (история `odds/<id>/<время>.json`). Не чаще раза в несколько минут.
   - Если есть `analysis/<id>.html` — пересобирает страницу анализа; иначе только печатает текст.
   - Расписание и таблицу на странице турнира обновляет `python scripts/render_schedule.py --league <id>`.
4. **Оформить рекомендации** по каждому интересующему матчу (по умолчанию — ближайшие 2–3 дня). Данные брать из вывода `--text` и `odds/<id>/latest.json` (`rows`: рынок, коэффициенты, `line` — вероятность без маржи, `est` — частота по статистике, `n`, `signal`, `ev`).

5. **Сохранить прогноз и результат.** `python scripts/forecast.py --league <id>` создаёт `forecasts/<id>/<event_id>.json` по каждому матчу (один раз, существующие не перезаписываются — прогноз фиксируется до игры), подставляет результат сыгранных карт и отмечает, зашли ли подсказки, затем пересобирает страницы `matches/<id>/<event_id>.html` (кликабельны из расписания на странице турнира). Свой разбор вместо шаблонного текста: `python scripts/forecast.py --league <id> --event <event_id> --note "текст"`. Запускать после каждого скачивания линии и после игр (с `collect_team.py --refresh`, чтобы появились результаты).

## Как читать и что писать

- Три блока на матч: **победа на карте/серии**, **время** (рынки «Время карты больше N мин»), **убийства** («Тотал убийств больше N»).
- Рекомендовать сторону только при перевесе «явный» или «небольшой»; «нет перевеса» — писать «статистика не расходится с линией». Для каждого пункта: рынок, коэффициент, линия vs статистика, выборка (`n` карт), перевес.
- Выборки малые (на турнире 2–4 карты у команды): если на турнире < 6 карт, скрипт сам берёт карты команды со всех турниров — об этом сказать. Если `n` < 10 — отметить низкую надёжность.
- Победа считается по log5 из винрейтов карт и не учитывает силу соперников — это грубая оценка; для победы дополнительно сверить с реальным классом команд (серии, соперники) из `reports/<id>/<team>.html`.
- В колонках `c1`/`c2` для победы стоят «1»/«2» (первая/вторая команда матча в заголовке), для тоталов — «Б/М» (больше/меньше) и «Да/нет».
- Определения «первая башня» и «Beyond Godlike» из OpenDota могут не совпадать с правилами PARI.
- Матч, у которого время начала уже прошло, может быть в игре — рынки по картам в линии устаревают; отметить это.
- Это разбор статистики, а не гарантия исхода и не призыв ставить: в конце одной фразой напомнить, что маржа букмекера ~8% и выборки малы. Не называть сумм и не обещать прибыль.

## Формат ответа

Короткий список матчей по времени (МСК): пара, время, затем 3 строки (победа / время / убийства) с вердиктом и числами; в конце — 1–3 самых сильных наблюдения. Таблицу целиком не дублировать — полный вид на `reports/<id>/analysis.html`, если страница анализа есть.
